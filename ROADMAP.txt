2. DATA FACTS (confirmed from the WOA23 Product Documentation PDF and the NCEI download pages)
---------------------------------------------------------------------------------
 - File name woa23_[span]_[v][tp]_[gr].nc : v = t / s / o; tp 00 annual, 01-12 months, 13-16 seasons (Jan-Mar, Apr-Jun, Jul-Sep, Oct-Dec; northern-
   hemisphere seasons); gr 01 = 1 degree.  We use field "an" (objectively analysed): t_an, s_an, o_an.
 - Depth levels (Table 4): annual T, S, O = 0-5500 m (102 levels); seasonal T, S = 102 levels but O = 0-1500 m (57); monthly T, S, O = 0-1500 m (57).
   The 57 monthly levels are the first 57 annual levels.
 - Time spans: T, S exist for decades 1955-64 ... 2015-22, decav (1955-2022) and 30-year normals; 'all' (1965-2022) does NOT exist for T, S.
   Oxygen exists ONLY for 1971-2000 (decav71A0) and 'all'. The only span common to T, S, O is decav71A0 (1971-2000) - this is what we use.
 - Everything is a climatology: "monthly" = mean of that month over the span, not a time series. Oxygen units: umol/kg. No oxygen holes inside the ocean.
 - Nutrients exist only at 1 degree and only for 'all'; 0.25 degree exists only for T and S. Not planned.

3. OPEN ITEMS, PRIORITISED
---------------------------------------------------------------------------------
 First measure, then optimise: everything so far ran on a software renderer. Target machines are normal user laptops (integrated GPUs, browsers), so
 the first useful input is how the live site feels on such a laptop (frame rate with several selections, High quality, monthly playback, 0.4 GB of
 graphics memory in monthly mode). R4 and R8 below matter more because of this.

 P1  Next, highest value for the project goal
 ---------------------------------------------------------------------------------

 R1. DROPPED (user decision 2026-11-26): "AND" combination of selections across diagrams. Kept only as a record; the text below is not planned.
     Why: water-mass identification needs "this T-S water that is also low in oxygen"; today selections are drawn as a union.
     How: a selection group whose members must all contain the voxel (per-voxel test over the group's diagrams); render as a volume
     first (fiber surfaces of an intersection need a combined distance: max of the signed distances is a valid distance-like field for
     "inside all"). UI: tick several list rows, "Combine (AND)". Touches 6.3 (items), 6.4 (list), 7.5 (march), 8.2 (upload).
     Risk: more per-sample work; keep within the existing caps.
 R2. Real multidimensional transfer function for rectangles                M      old 2.2
     Per-rectangle opacity, soft (feathered) edges instead of nearest-filtered region texture, optional gradient shading, so a volume looks
     like a water mass rather than a flat tint. Touches 4.6, 6.3 (item gets opacity / softness), 7.5 (volume branch), 6.4.
 R3. Editable 1D transfer function (colour + opacity points)               M      old 2.3
     Small canvas editor producing the 256x1 table (today: fixed colour map, constant opacity, window sliders). Touches 4.5, 7.5, 8.4, 11.
 R4. Performance, after measuring on a real GPU                            M
     Options in order of benefit / cost: empty-space skipping with a coarse min / max brick texture (skip bricks whose T, S, O range cannot touch
     any selection or the 1D window); adaptive step near surfaces (|distance|-based); frame-time readout; cache uniform locations (U Proxy calls
     getUniformLocation on every access); half-resolution policy while playing. Touches 4.2, 7.5, 12.1. Risk: skipping bounds must be
     conservative or surfaces vanish; verify with before / after pictures (the measurement scripts used in D31 can be reused).
